# MC&DJ ERP Brand Guidelines

Versión 1.0

---

# Propósito

Este documento define las reglas oficiales de identidad visual del MC&DJ ERP.

Su objetivo es traducir el Manual de Marca institucional a reglas claras para desarrollo de software, diseño de interfaces y asistentes de inteligencia artificial.

Toda modificación visual del ERP deberá respetar este documento.

Si existe alguna contradicción entre este documento y el Manual de Marca oficial de MC&DJ, prevalecerá siempre el Manual de Marca.

---

# Filosofía de la marca

MC&DJ representa:

- Profesionalismo
- Confianza
- Precisión
- Cercanía
- Innovación
- Tecnología
- Orden

El ERP debe transmitir exactamente esos mismos valores.

No buscamos una interfaz llamativa.

Buscamos una interfaz elegante, limpia y extremadamente funcional.

---

# Identidad del ERP

La página web comercial y el ERP forman parte de la misma marca, pero tienen objetivos distintos.

## Sitio Web

Objetivo:

- Generar confianza comercial.
- Captar clientes.
- Transmitir cercanía.

Color predominante:

Amarillo institucional.

---

## ERP

Objetivo:

- Operación diaria del despacho.
- Rapidez.
- Productividad.
- Concentración.
- Tecnología.

Color predominante:

Azul institucional.

---

# Regla principal

Toda pantalla deberá ser reconocible inmediatamente como parte del ecosistema MC&DJ.

Sin embargo, el ERP deberá diferenciarse claramente del sitio web comercial.

---

# Paleta institucional

Únicamente podrán utilizarse colores aprobados en el Manual de Marca.

No inventar nuevos colores corporativos.

No modificar tonalidades institucionales.

No utilizar gradientes como elemento principal.

---

## Color principal ERP

Azul institucional.

Uso:

- Botones principales.
- Sidebar.
- Elementos activos.
- Calendarios.
- Links importantes.
- Indicadores principales.

---

## Amarillo institucional

Uso exclusivo para:

- Elementos destacados.
- Reconocimiento de marca.
- Llamadas importantes.

No utilizar como color dominante dentro del ERP.

---

## Naranja institucional

Uso exclusivo para:

- Advertencias.
- Acciones importantes.
- Estados intermedios.

Nunca utilizar como color principal.

---

## Gris oscuro institucional

Uso:

- Texto.
- Sidebar.
- Iconos.
- Encabezados.

---

## Blanco

Será el color predominante de los fondos.

La interfaz debe respirar.

Evitar pantallas saturadas.

---

# Estados

Los estados funcionales no forman parte del branding.

Pueden utilizar colores convencionales.

Éxito

Verde.

Advertencia

Naranja.

Error

Rojo.

Información

Azul.

Estos colores nunca sustituyen la identidad institucional.

---

# Logotipos

Siempre utilizar archivos oficiales.

Nunca:

- Modificar proporciones.
- Cambiar colores.
- Agregar sombras.
- Agregar efectos.
- Deformar.
- Rotar.
- Cambiar tipografía.

---

# Isotipo

El isotipo podrá utilizarse como:

- Favicon.
- Loader.
- Pantallas vacías.
- Dashboard.
- Iconografía institucional.

Siempre respetando proporciones.

---

# Tipografía

Utilizar la tipografía institucional.

Cuando no esté disponible utilizar únicamente el fallback autorizado por el proyecto.

Nunca mezclar múltiples familias tipográficas.

Toda la aplicación deberá mantener consistencia.

---

# Espaciado

El ERP utilizará un sistema uniforme de espaciado.

Todo componente deberá seguir la misma retícula.

Nunca utilizar márgenes arbitrarios.

---

# Bordes

Preferir esquinas ligeramente redondeadas.

Evitar diseños excesivamente cuadrados.

El estilo general debe transmitir modernidad sin perder sobriedad.

---

# Sombras

Utilizar sombras suaves.

Nunca utilizar sombras pronunciadas.

La jerarquía deberá generarse principalmente mediante espaciado y color.

---

# Iconografía

Toda la iconografía deberá pertenecer a una misma familia.

No mezclar diferentes estilos.

Preferir iconografía lineal.

---

# Fotografía

El ERP utilizará muy pocas fotografías.

La prioridad serán:

- Iconos.
- Gráficos.
- Indicadores.
- Tablas.
- Dashboards.
- Calendarios.

---

# Filosofía UX

El usuario deberá comprender cualquier pantalla en menos de diez segundos.

Toda pantalla deberá responder inmediatamente:

- ¿Qué está ocurriendo?
- ¿Qué puedo hacer?
- ¿Qué debo hacer después?

---

# Principios UX

- Eliminar ruido visual.
- Eliminar elementos innecesarios.
- No duplicar acciones.
- No mostrar botones que el usuario no puede utilizar.
- Priorizar la lectura rápida.
- Mostrar únicamente la información necesaria.

---

# Navegación

Toda la navegación deberá permanecer consistente.

- Sidebar.
- Header.
- Dashboard.
- Menús.
- Modales.

Todos deberán compartir comportamiento.

---

# Dashboard

El Dashboard será el centro operativo del ERP.

No deberá saturarse de información.

Los indicadores deberán ser claros.

Las tarjetas deberán mantener el mismo diseño.

---

# Agenda

La Agenda NOMIPAQ será la referencia visual para futuros calendarios.

Todos los calendarios futuros deberán reutilizar los mismos componentes.

---

# Formularios

Todos los formularios compartirán:

- Espaciado.
- Tipografía.
- Botones.
- Validaciones.
- Mensajes.
- Comportamiento.

Nunca crear formularios con estilos independientes.

---

# Tablas

Las tablas deberán privilegiar la lectura.

No abusar de líneas.

Utilizar suficiente espacio en blanco.

Permitir:

- Ordenamiento.
- Búsqueda.
- Responsive.

Exportación cuando tenga sentido.

---

# Botones

## Botón Primario

Acción principal.

---

## Botón Secundario

Acción alternativa.

---

## Botón Peligro

Eliminar.

Cancelar definitivamente.

Nunca utilizar varios botones primarios en una misma vista.

---

# Responsive

Desktop será la experiencia principal.

Tablet completamente funcional.

Mobile totalmente usable.

No ocultar funcionalidades importantes únicamente por tamaño de pantalla.

---

# Accesibilidad

Todos los componentes deberán cumplir:

- Contraste suficiente.
- Estados hover.
- Estados focus.
- Navegación por teclado.
- Mensajes claros.
- No depender únicamente del color para comunicar estados.

---

# Componentes reutilizables

Todo componente visual deberá formar parte del Design System.

Nunca duplicar componentes.

Nunca copiar código visual entre módulos.

Toda mejora realizada a un componente deberá beneficiar automáticamente a todo el ERP.

---

# Inteligencia Artificial

Los asistentes de IA que participen en el desarrollo deberán respetar estas reglas.

Nunca generar interfaces incompatibles con este documento.

Si existe duda entre una decisión visual y este documento, deberá priorizarse este documento.

---

# Principio rector

El usuario nunca debe pensar que está utilizando una aplicación desarrollada por módulos independientes.

Debe sentir que todo el ERP fue diseñado como un único producto desde el primer día.
